# Markdown 渲染与公式排版规范

[返回学习目录](../README.md)

本仓库以 GitHub 上的实际阅读效果为基准。正文尽量使用标题、表格、段落和图示建立层次，避免依赖不同预览器对强调符号的宽松容错。

## 正文与强调

章节用 `#`、`##`、`###` 等标准标题表示。习题中的“题目、标准答案、解析”使用四级标题独立成段。少量需要强调的短语可以使用 HTML 的 `<strong>重点内容</strong>` 标签；不使用成对星号作为强调符号。

数学变量、较短的计算式、伪代码标识符使用行内代码格式或 Unicode 数学符号。示例：`A₁=0`、`ρ=14/24≈58.33%`。这类表达不依赖额外的数学渲染器。

## 较长公式：统一使用 GitHub 原生 math 公式块

GitHub 官方支持 MathJax 和带 `math` 语言标记的围栏公式块。下面的完整写法可直接在仓库 Markdown 中使用：

```math
\overline{Q}=\frac{1}{T}\int_{0}^{T}Q(t)\,dt
```

约定：

1. 在公式前后各留一个空行，不把中文标点或解释文字直接写进公式围栏。
2. 分式完整写成 `\frac{a}{b}`，上下标尽量写成 `_{i}`、`^{2}`，减少歧义。
3. 单位放在正文中说明；公式中确需单位时，使用例如 `\mathrm{min}` 的拉丁字母单位。
4. 不把 HTML 转义串混入公式。比较符号在公式块内直接写，例如 `a>b`。
5. 一道复杂公式写一个块，避免在 Markdown 表格单元格中插入围栏公式。

## 图解与核对

流程拓扑和事件循环使用 Mermaid，精确时间线、队长阶梯曲线等采用 SVG。所有图的文字描述需与正文的数值表一致。

提交修改前，在仓库根目录运行：

```bash
python scripts/check_markdown.py
```

检查器会识别残留的强调分隔符、原始数学定界符、未闭合的代码围栏、明显不规范的分式和数学公式花括号。这个静态检查不能证明所有 MathJax 公式都语义正确，还需结合计算结果与实际 GitHub 页面抽检。
