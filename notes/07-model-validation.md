## 先区分两个概念：Verification 与 Validation（课件第 1—2 页）

一个仿真模型运行正常，甚至能生成很多看似合理的数据，并不意味着它能够代表实际系统。评价模型时，首先需要区分两个不同的问题。

| 概念 | 中文名称 | 要回答的问题 | 主要检查对象 |
| --- | --- | --- | --- |
| Verification | 验证 | 仿真程序有没有正确执行已经规定的模型逻辑？ | 程序实现、事件规则、状态更新、计算过程 |
| Validation | 确认 | 所建立的模型能否足够准确地描述现实系统？ | 模型结构、假设、输入数据、输出与实际的差异 |

例如，为一个单服务台系统编写仿真程序。程序能够按到达顺序分配服务、正确更新等待队列，说明程序的逻辑可能通过了验证。但是，如果现实中存在优先级插队，而模型始终采用先到先服务，那么程序即使完全没有错误，模型也未必得到确认。

两者的先后关系是：先检查程序是否正确实现模型，再检查这个模型是否足以代表现实。不过，在建模过程中它们可以反复进行，而不是只能各做一次。

## 7.1 仿真模型的验证（课件第 3—8 页）

验证的目标是检查仿真程序的逻辑正确性，发现并排除实现过程中的问题。课件列出五项工作。

### 7.1.1 使用子程序编写与调试

课件第 4 页强调由简到繁、逐步深入。不要在所有模块尚未检查的情况下，就把一个复杂系统整体运行并仅凭最终结果判断程序是否正确。

具体来说，可以先确认主程序和关键子程序的基本规则是否正确，再逐步加入其他功能。例如，对于离散事件仿真，可以先检查到达事件与服务完成事件是否能按时间推进，再检查等待队列、服务台状态以及统计量的更新。

这样分步调试的原因，是每次只增加少量逻辑。如果新增一个模块后结果出现异常，就能将检查范围缩小到最近新增的部分。

这里所说的子程序不一定是某种特定编程语言的函数；在 Arena 等图形化仿真软件中，也可以把它理解为能够单独检查的流程段或模块组合。

### 7.1.2 检查主要参数的输出

课件第 5 页要求，在仿真运行中检查主要输出及其响应是否合理，特别提到设备利用、排队情况和系统内实体数量的变化。

以排队系统为例，不能只检查最后得到的平均等待时间，还应同时观察：

| 观察量 | 应当检查什么 |
| --- | --- |
| 服务台利用情况 | 服务台何时忙碌、何时空闲，是否符合加工过程 |
| 等待队列 | 顾客到达、开始服务、离开队列时，队长是否正确变化 |
| 系统内实体数 | 到达增加实体、离开减少实体，人数变化是否前后一致 |
| 参数改变后的输出 | 到达量、处理能力等主要参数变化时，模型响应是否符合预期逻辑 |

这里的“合理”首先是程序层面的检查。例如，同一个顾客不能同时占用两台互斥服务设备；如果没有顾客到达，模型不应凭空增加正在服务的顾客。

### 7.1.3 运行时跟踪检查（Trace）

课件第 6 页要求追踪系统状态和参数的动态变化过程，而不只是检查仿真结束后的汇总表。许多仿真语言都提供事件或状态跟踪功能。

对于事件驱动系统，跟踪记录可以按事件顺序写成：

| 检查项目 | 记录的内容 |
| --- | --- |
| 当前仿真时刻 | 事件发生的时刻与推进顺序 |
| 当前事件 | 到达、开始服务、服务完成等 |
| 资源状态 | 忙碌或空闲，以及正在服务的实体 |
| 队列状态 | 队列中的人数和排列顺序 |
| 系统状态 | 系统内实体总数及其增减 |

课件给出的典型逻辑错误是“系统中有顾客而服务台却空闲”。对一个顾客可立即占用空闲服务台的普通队列模型，这通常说明事件规则或队列分配存在问题。但判断时仍应结合模型规定的服务资格、停机状态或其他限制，不能把所有空闲一概视为错误。

跟踪检查的操作要点是：找到出现异常的第一个事件时刻，再检查该事件之前与之后的状态更新。这样通常比从最终平均数倒推错误更直接。

### 7.1.4 分类测试

课件第 7 页把测试分为四类，每一类检查的重点不同。

| 测试类型 | 课件要求 | 主要检查目的 |
| --- | --- | --- |
| 基本测试 | 跟踪单一实体，使用常量数据，改变各种参数 | 用容易手算的数据检查最基本的执行规则 |
| 情景测试 | 使用不同输入数据进行长时间运行 | 观察超长队列、资源长时间闲置等异常情形 |
| 极端情况测试 | 让系统在超负荷等极端条件下运行 | 检查边界状态与压力状态下的模型逻辑 |
| 动态行为测试 | 利用动画观察运行过程 | 检查实体移动、资源占用与流程转换是否符合模型规定 |

基本测试中使用常量数据尤其重要。例如，固定所有到达间隔与服务时间后，随机波动被排除，可以逐项手算顾客的到达、开始服务和完成服务时刻，再与程序输出对照。

情景测试和极端情况测试并不要求模型始终显示“好”的绩效。若系统处理能力明显不足，出现不断累积的队列本身可能是正确结果；需要检查的是队列增长的机制有没有按规则执行，以及程序能否正确处理这种状态。

动态行为测试所用动画也不只是展示效果。若观察到实体穿过不该经过的工序，或资源尚未释放便开始处理另一项互斥任务，这些现象可以直接提示程序逻辑问题。

### 7.1.5 验证活动的验收

课件第 8 页提出，验证活动及其结论应通过客户小组会等方式获得客户认可。

验收时需要说明检查了哪些模块、使用了什么测试情景、发现并修复了什么问题，以及目前的验证结论。客户的认可意味着相关方接受这一轮程序验证活动，并不自动证明模型对现实系统的描述已经准确。后一问题仍属于模型确认的范围。

## 7.2 仿真模型的确认：“三步法”（课件第 9—12 页）

模型确认并不是检查程序是否报错，而是反复比较仿真模型与实际系统，并利用差异调整模型，使其对实际系统的描述更加准确。课件把确认过程概括为三个步骤。

### 7.2.1 第一步：直观考察模型的有效性

课件第 10 页强调两个方面：直观合理性和灵敏度分析。

所谓直观合理性，是让了解实际系统的使用者参与判断。模型中有哪些实体、资源、业务规则和限制条件，事件发生的先后关系是什么，这些内容应能让熟悉业务的人理解，并且与其经验相符。

灵敏度分析则是主动改变输入或模型参数，观察输出变化的方向与趋势是否合理。例如，在其他条件相同的前提下，提高服务能力后，如果模型反而持续出现更长的等待队列，就需要检查发生这种变化的机制。这里关注的不只是某个数值是否相等，而是输入与输出之间的反应关系是否符合系统机理。

这一步能够发现明显不合理的结构或响应，但不能单凭“看起来像”就断定模型有效。因此还需要后两步。

### 7.2.2 第二步：检验模型假设

课件将模型假设分为两类。

结构假设（Structural Assumptions）来自对实际系统的简化和抽象。例如，是否将若干服务环节合并为一个环节，是否忽略某些资源约束，是否假设所有顾客都按相同规则排队。检查这些假设时，应判断简化是否保留了影响研究结果的关键机制。

数据假设（Data Assumptions）指输入数据的数值或概率分布。例如，到达间隔与服务时间采用什么分布，分布参数取什么值，输入样本是否能够代表真实业务情境。即使模型结构正确，错误的数据假设仍可能导致不可信的仿真输出。

这里要区分两种不同的错误：结构假设不合适，通常需要修改系统逻辑；数据假设不合适，通常需要重新检查实际样本、参数估计或输入分布。二者并不总能通过调整某一个参数互相弥补。

### 7.2.3 第三步：比较模型输出与实际数据

课件第 12 页建议充分利用现有系统的历史数据。通常将一组历史数据用于模型校准（Calibration），另一组数据用于模型确认（Validation）。

校准的作用是根据实际数据调整模型，使它更好地符合已知系统；确认则是用另一组数据检查调整后的模型是否仍能有效反映实际系统。如果始终在同一组数据上修改模型并评价模型，就难以判断它能否代表未参与校准的实际情形。

如果现实中的完整系统与拟建模型不完全相同，但二者具有大量相同子系统，课件建议先针对这些子系统建立模型并分别确认，再进行组合。这样可以先确认已经能够观察和比较的部分，再逐步处理整体系统的差异。

第 7.3 节给出比较模型输出与实际数据的两种具体统计方法。

## 7.3 仿真输出数据与实际数据的比较方法（课件第 13—24 页）

### 7.3.1 方法一：使用拟合输入数据的理论分布进行确认

课件第 14 页首先指出一个基本前提：实际系统与仿真模型必须在类似的输入条件下进行比较。如果两边面对的输入条件不同，即使最终输出存在差异，也难以判断差异是模型造成的，还是输入条件造成的。

因此，比较时先固定一组决策变量，即模型中可控制的设置。课件用排队系统举例，决策变量可以是服务台数量、队列数量、排队规则等。然后让实际系统按客观发生的过程运行，让仿真模型按拟合的输入概率分布运行，选择一个主要性能指标作为确认准则。

假设实际系统这一性能指标的基准值为 `μ₀`。对仿真模型进行 `R` 次独立重复运行，每次记录 `n` 个输出。记第 `r` 次运行中第 `i` 个输出为 `Yᵣᵢ`。

第一步，计算各次独立运行的均值：

```math
\overline Y_r=\frac{1}{n}\sum_{i=1}^{n}Y_{ri},
\qquad r=1,2,\ldots,R
```

第二步，计算 `R` 个运行均值的总平均：

```math
\overline Y=\frac{1}{R}\sum_{r=1}^{R}\overline Y_r
```

第三步，计算各次运行均值之间的样本方差和标准差：

```math
S^2=\frac{1}{R-1}\sum_{r=1}^{R}
(\overline Y_r-\overline Y)^2,
\qquad S=\sqrt{S^2}
```

课件第 16 页建立原假设：

```math
H_0:E(Y)=\mu_0
```

这表示仿真输出的总体均值与实际系统基准值一致。进行双侧检验时，与之对应的备择假设是：

```math
H_1:E(Y)\ne\mu_0
```

当单次运行的观测量 `n` 足够大时，各次运行均值可以近似服从正态分布；每次重复使用独立的随机数流，因而这些运行均值可以近似看作相互独立。在这样的条件下，使用单样本 `t` 统计量：

```math
\boxed{
t=\frac{\overline Y-\mu_0}{S/\sqrt R}
}
```

在原假设成立且相应正态近似适用时，统计量近似服从自由度为 `R−1` 的 `t` 分布：

```math
t\sim t_{R-1}
```

给定显著性水平 `α`，双侧检验的判定规则为：

```math
\boxed{
|t|>t_{1-\alpha/2}(R-1)
}
```

也就是说，将仿真均值与实际基准之间的差额，除以仿真运行均值的标准误。如果这一标准化差异的绝对值超过临界值，就认为两者的均值存在统计上显著的差异。

反过来，未达到拒绝条件只能说明当前样本没有提供足够证据认定两者不同，不等于证明两者完全相同。还应结合实际业务对误差大小的要求判断模型能否接受。

注意：课件把 `μ₀` 作为已给定的实际性能基准，因此使用上述单样本检验；如果 `μ₀` 本身也只是有较大抽样误差的估计值，这个公式就没有包含实际基准的不确定性，不能不加检查地照搬。

### 7.3.2 方法二：直接使用历史输入数据进行确认

与上一种方法不同，课件第 20 页的第二种方法不再让仿真模型仅依照拟合的理论分布自行产生输入，而是将实际系统记录的输入数据保存到数组或文件中，并在仿真运行时将这些真实历史输入逐组调入模型。

例如，把某段历史中的实际到达间隔、实际服务时间等输入序列交给仿真模型，使实际系统与仿真模型面对同一组输入条件，再比较双方的输出。这种比较建立在对应关系上，因此要使用配对（匹配）检验。

假设共收集 `k` 组历史输入数据，并以它们分别进行同步仿真。对第 `j` 组输入：

`Zⱼ` 表示实际系统对应该组输入的响应样本均值；`Yⱼ` 表示仿真模型对应该组输入的响应样本均值。二者必须是同一项性能指标，具有相同的计量单位。

第一步，对每组历史输入计算一对实际—仿真的差值：

```math
d_j=Z_j-Y_j,
\qquad j=1,2,\ldots,k
```

第二步，计算这 `k` 个配对差的样本均值：

```math
\overline d=\frac{1}{k}\sum_{j=1}^{k}d_j
```

第三步，计算配对差的样本方差与标准差：

```math
S_d^2=\frac{1}{k-1}\sum_{j=1}^{k}
(d_j-\overline d)^2,
\qquad S_d=\sqrt{S_d^2}
```

设配对差的总体均值为 `μ_d=E(d_j)`，课件第 23 页提出：

```math
H_0:\mu_d=0,
\qquad H_1:\mu_d\ne0
```

如果原假设成立，意味着实际系统与仿真模型的平均配对差为零。采用配对 `t` 统计量：

```math
\boxed{
t=\frac{\overline d}{S_d/\sqrt k}
}
```

在适用条件下，其分布近似为：

```math
t\sim t_{k-1}
```

双侧检验的拒绝域是：

```math
\boxed{
|t|>t_{1-\alpha/2}(k-1)
}
```

### 7.3.3 为什么要对差值检验，而不是把两组结果拆开检验

实际系统的第 `j` 个输出均值 `Zⱼ` 与仿真模型的第 `j` 个输出均值 `Yⱼ`，来自同一组历史输入，因此存在明确的一一对应关系。把它们相减，可以使两边共同面对的输入波动在差值中部分抵消。此时真正用于统计检验的样本是：

```math
d_1,d_2,\ldots,d_k
```

课件第 22 页说明了使用配对 `t` 检验的三个统计理由。

第一，各组输入都来自所研究的同一系统，因此相应差值可以近似视为同分布。

第二，如果这 `k` 组历史输入在时间上没有重叠，并且组间不存在其他显著依赖关系，可以将各组差值近似视为独立。

第三，`Zⱼ` 与 `Yⱼ` 本身都是相应一组数据的样本均值；每组包含足够多观测时，可采用正态近似，继而对差值使用 `t` 检验。

因此，这里自由度是 `k−1`，不是实际系统与仿真系统观测总数减一。配对检验利用的是每组输入下“两边差多少”，而不是把所有实际输出和所有仿真输出当成互不相关的两批数据。

### 7.3.4 两种确认方法的区别

| 比较内容 | 使用拟合输入的理论分布 | 使用历史输入数据 |
| --- | --- | --- |
| 仿真输入 | 由拟合后的概率分布生成 | 将记录的实际历史输入交给模型 |
| 实际系统数据 | 一个性能指标的实际基准 `μ₀` | 每组历史输入对应的实际输出均值 `Zⱼ` |
| 仿真数据 | `R` 次独立运行的均值 `Ȳᵣ` | 与实际数据成对的 `k` 个仿真输出均值 `Yⱼ` |
| 检验对象 | 仿真总体均值是否等于 `μ₀` | 实际—仿真配对差的总体均值是否为零 |
| 统计方法 | 单样本 `t` 检验 | 配对 `t` 检验 |
| 自由度 | `R−1` | `k−1` |

两种方法的目的相同，都是检查模型输出是否与现实相符；差异在于如何构造具有可比性的输入与输出，以及最后把什么量当作统计样本。

### 7.3.5 使用历史数据时的注意事项（课件第 24 页）

课件最后强调，首先必须核对历史数据的真正含义。例如，企业系统中用于会计或计划的标准作业时间，不一定是车间现场实际发生的加工时间。如果将标准数据误当作真实运行数据，再用它们确认仿真模型，就可能得到没有实际说服力的结论。

其次，在现场数据缺失或其他条件限制下，如果暂时无法直接确认模型，应尽可能做好程序验证，并请最熟悉实际系统的人员判断模型的结构、规则和输出是否合理。这可以为模型可信度提供部分依据，但应明确哪些方面尚未得到实际数据的直接确认。

## 7.4 将“验证”落实到一张事件跟踪表

课件第 4—7 页介绍的分模块调试、输出检查、事件跟踪和分类测试，最终都要回答同一个问题：程序执行的每一步是否符合我们事先规定的系统规则？只看最后一个平均数，很难发现错误发生在什么位置。对离散事件仿真而言，一张短小、可以手算的事件表通常最有效。

### 7.4.1 单服务台确定性案例：从每个事件检查状态

考虑一个先到先服务（FCFS）的单服务台。服务不可中断，服务台空闲时到达的顾客立即开始服务。三个顾客的到达时刻、服务时间如下。为保证可手算，本例没有随机输入。

| 顾客 | 到达时刻 | 服务时间 | 开始服务 | 完成服务 | 等待时间 |
| --- | ---: | ---: | ---: | ---: | ---: |
| A | 0 | 4 | 0 | 4 | 0 |
| B | 2 | 3 | 4 | 7 | 2 |
| C | 3 | 2 | 7 | 9 | 4 |

这里的开始服务时刻不是直接给定的，而是按 FCFS 规则计算。例如 B 虽然在时刻 2 到达，但服务台直到时刻 4 才释放，所以 B 必须等待两单位时间。C 在时刻 3 到达，等待 A 和 B 完成以后才能服务，因此要到时刻 7 才开始。

再把程序每个事件执行后的状态写下来。用 `N` 表示系统中顾客总数，用 `Q` 表示等待队列人数，不含正在接受服务的顾客。

| 时刻 | 刚发生的事件 | 服务台状态（事件处理后） | Q | N |
| ---: | --- | --- | ---: | ---: |
| 0 | A 到达 | A 正在服务 | 0 | 1 |
| 2 | B 到达 | A 正在服务 | 1 | 2 |
| 3 | C 到达 | A 正在服务 | 2 | 3 |
| 4 | A 完成服务 | B 开始服务 | 1 | 2 |
| 7 | B 完成服务 | C 开始服务 | 0 | 1 |
| 9 | C 完成服务 | 空闲 | 0 | 0 |

这张表至少允许我们进行三项相互独立的核对。

第一，实体守恒。到任意时刻，已到达顾客数减去已离开顾客数，必须等于系统内顾客数。如果不考虑顾客放弃、转移等特殊机制，则有：

```math
N(t)=A(t)-D(t)
```

其中 `A(t)` 是截至时刻 `t` 的累计到达人数，`D(t)` 是累计完成并离开的人数。比如时刻 4 处理完 A 的离开事件以后，累计到达 3 人、离开 1 人，所以系统里应有 2 人。

第二，资源和队列状态要相互匹配。若 `B(t)` 表示正在服务的顾客人数，则：

```math
N(t)=Q(t)+B(t),\qquad B(t)\in\{0,1\}
```

在本例中，只要 `Q(t)>0`，服务台就不能无故保持空闲；但这条规则建立在服务台没有停机、没有服务资格限制、顾客没有暂缓处理的前提上。若模型包含这些机制，就应检查符合该机制的状态约束，而不是机械套用简单队列规则。

第三，可以用不同统计途径计算同一指标，检查是否得到一致答案。三个顾客的等待时间分别为 0、2、4，因此：

```math
\overline W_q=\frac{0+2+4}{3}=2
```

如果程序统计的是时段 `[0,9]` 内的时间平均队长，也可以计算队长曲线下的面积。时刻 2—3 队列里有 1 人，时刻 3—4 有 2 人，时刻 4—7 有 1 人，其余时段队列为空。因此：

```math
\int_0^9Q(t)\,dt=1\times1+2\times1+1\times3=6
```

```math
\overline Q=\frac{1}{9}\int_0^9Q(t)\,dt
=\frac{6}{9}=\frac{2}{3}
```

同一个队列面积，也等于三个已完成顾客的等待时间之和 `0+2+4=6`。这个案例中，所有顾客在观察窗口内到达并完成服务，因此这两个计算结果应该严格相同。若程序报告的等待时间总和不是 6，或者队长曲线面积不是 6，就至少有一个事件更新或统计累积步骤需要检查。

这里可以看到三种层次的证据：事件表检查执行顺序，守恒关系检查状态更新，重复计算检查统计量。三者都属于程序验证，仍然不能证明 FCFS 的业务规则就一定适合现实系统。

### 7.4.2 四类测试分别应该怎样设计

围绕刚才的队列模型，可以把课件中的四种测试直接落实为不同实验。

| 测试 | 对程序施加的条件 | 预期观察与检查 |
| --- | --- | --- |
| 基本测试 | 仅输入 1 位顾客，固定其服务时间 | 顾客立即服务、等待为 0、完成时刻等于到达时刻加服务时间 |
| 情景测试 | 分别使用低到达率、高到达率和波动性较强的输入序列 | 在不同运行情境下队列、资源利用和事件数量均保持逻辑一致 |
| 极端测试 | 服务时间为零（若模型允许）、连续大量顾客同时到达、到达率远大于处理能力 | 检查同刻事件顺序、积压队列、边界输入及程序是否失效 |
| 动态行为测试 | 在动画中逐个观察实体进入、排队、开始服务与离开 | 流程路径、占用和释放资源的时刻与事件表相符 |

如果模型没有定义“服务时间为零”这种输入，不能简单要求程序处理它；此时应先明确模型可接受的输入范围。对一个尚未完成验证的模型，不应仅因为极端输入下出现很长的队列，就把该结果视为程序错误。

### 7.4.3 自动检查：把业务规则写成不变量

“不变量”是指模型运行过程中应当始终成立的关系。每处理一个事件就检查一次这些关系，可以比人工盯住最终报表更早发现问题。对最简单的单服务台模型，可能包括：

```math
N(t)\geq0,\qquad Q(t)\geq0,
\qquad B(t)\in\{0,1\}
```

```math
N(t)=Q(t)+B(t)
```

```math
T_i^{\mathrm{start}}\geq T_i^{\mathrm{arrival}},
\qquad
T_i^{\mathrm{finish}}=T_i^{\mathrm{start}}+S_i
```

`S_i` 为第 `i` 位顾客的服务时间。对于具有优先级、故障、批处理、返工或顾客放弃的模型，需要建立符合其实际逻辑的检查关系。例如，顾客放弃后必须明确它是否计入离开总量，否则最简单的实体守恒公式也会被误用。

## 7.5 两种模型确认检验：从数据到统计决策

第 7.3 节已经给出两个公式。真正做题时，容易出现的问题是：不知道哪一列数据才是独立样本、把样本方差与标准误混为一谈、使用错误的自由度，或者把“不拒绝零差异”理解成“模型得到确认”。下面用两道完整计算题串起所有步骤。

### 7.5.1 例题一：使用拟合分布，进行单样本 t 检验

某服务系统实际记录的平均等待时间基准为 10 分钟。研究人员按照课件第一种确认方法，用拟合的到达与服务时间分布生成输入，独立重复仿真 6 次。各次运行得到的平均等待时间分别为：

```math
8,\ 9,\ 10,\ 7,\ 11,\ 9
```

要求：在显著性水平 `α=0.05` 下，判断模型的平均等待时间是否与现实基准存在显著差异。已知 `t` 分布双侧检验临界值为 `t_{0.975,5}=2.571`。

第一步，识别统计样本。题目中的 6 个数是 6 次独立运行的均值，所以有效样本量是 `R=6`，而不是六次运行内部所有顾客的总人数。

第二步，计算六次运行均值的平均数：

```math
\overline Y=\frac{8+9+10+7+11+9}{6}=9
```

第三步，计算样本方差。六个观测与平均数 9 的差依次为 `-1,0,1,-2,2,0`，平方和是 10：

```math
S^2=\frac{1+0+1+4+4+0}{6-1}
=2
```

```math
S=\sqrt2\approx1.4142
```

第四步，提出双侧假设：

```math
H_0:\mu=10,\qquad H_1:\mu\ne10
```

第五步，计算标准误与检验统计量：

```math
SE(\overline Y)=\frac{S}{\sqrt R}
=\sqrt{\frac{2}{6}}\approx0.5774
```

```math
t=\frac{9-10}{0.5774}\approx-1.732
```

第六步，比较临界值。由于 `|t|=1.732<2.571`，因此在 5% 显著性水平下<strong>不拒绝</strong>两者平均值相等的原假设。这个结论只能说明样本尚未检测到显著差异。

还可以把结果改写为 95% 置信区间：

```math
\overline Y\pm t_{0.975,5}\frac{S}{\sqrt R}
=9\pm2.571\times0.5774
```

```math
\boxed{[7.516,\ 10.484]}
```

因为实际基准 10 分钟落在这个区间内，所以“不拒绝零差异”与置信区间结论一致。然而，这个区间同时允许模型的真实平均值低至 7.516 分钟，也允许其高至 10.484 分钟。若业务部门要求平均等待时间的误差控制在半分钟以内，仅凭此区间显然还不能认定模型已达到要求。

### 7.5.2 例题二：使用相同历史输入，进行配对 t 检验

某车间选择 5 个互不重叠且近似独立的历史运行时段。每个时段，模型读取与现场相同的到达、工序时间等历史输入，记录实际系统与模型的平均周转时间（分钟）：

| 历史时段 | 现场平均周转时间 `Zⱼ` | 仿真平均周转时间 `Yⱼ` | 差值 `dⱼ=Zⱼ−Yⱼ` |
| ---: | ---: | ---: | ---: |
| 1 | 10 | 9 | 1 |
| 2 | 9 | 10 | -1 |
| 3 | 13 | 11 | 2 |
| 4 | 11 | 11 | 0 |
| 5 | 14 | 11 | 3 |

要求：在 5% 显著性水平下，判断模型与现场是否有显著平均差异。已知 `t_{0.975,4}=2.776`。

第一步，确认存在一一配对。第 1 个现场值必须与第 1 个仿真值比较，第 2 个现场值与第 2 个仿真值比较，以此类推。每对结果使用同一历史时段的输入，不应先把现场的 5 个值与仿真的 5 个值打散。

第二步，计算 5 个配对差及其均值：

```math
d=(1,-1,2,0,3)
```

```math
\overline d=\frac{1-1+2+0+3}{5}=1
```

第三步，计算配对差的样本方差。差值相对其均值 1 的偏差是 `0,-2,1,-1,2`，平方和为 10：

```math
S_d^2=\frac{0+4+1+1+4}{5-1}=2.5
```

```math
S_d=\sqrt{2.5}\approx1.5811
```

第四步，建立检验假设：

```math
H_0:\mu_d=0,\qquad H_1:\mu_d\ne0
```

第五步，计算标准误与 t 值：

```math
SE(\overline d)=\frac{1.5811}{\sqrt5}
\approx0.7071
```

```math
t=\frac{1-0}{0.7071}\approx1.414
```

第六步，进行判断。`|t|=1.414<2.776`，所以不拒绝原假设；当前 5 组数据尚不能说明两者平均周转时间存在统计上显著的差异。

配对差的 95% 置信区间为：

```math
\overline d\pm t_{0.975,4}\frac{S_d}{\sqrt5}
=1\pm2.776\times0.7071
```

```math
\boxed{[-0.963,\ 2.963]}
```

这个区间包含 0，与 t 检验结论一致。同时，区间的正向上限接近 3 分钟，意味着现有样本对于平均偏差的估计仍较不精确。不能据此宣称模型与现场“误差接近于零”。

### 7.5.3 为什么例题二不能使用两独立样本 t 检验

如果简单把现场的五个均值当作一批独立观测，把仿真的五个均值当作另一批独立观测，就忽略了这十个数背后的配对关系。实际应关注的是：对同一历史时段的相同输入，模型与现场分别给出多少输出。

利用同组输入形成配对差，还可能抵消一部分共同输入波动。一般来说，差值方差可写为：

```math
\operatorname{Var}(Z-Y)
=\operatorname{Var}(Z)+\operatorname{Var}(Y)
-2\operatorname{Cov}(Z,Y)
```

当同一组输入使两边的结果正相关时，最后一项有助于减小差值方差，提高比较精度。这与第六讲的公共随机数法具有相似的统计结构，但这里的目的不是比较两套仿真方案，而是检查仿真模型与现实系统是否一致。

也要注意：按同一历史时段配对，并不能自动保证不同历史时段之间独立。例如，连续五天的产线负荷可能存在周期和持续性，五组差值就可能相关。此时必须重新设计分组或采用能够处理时间相关性的分析方法，不能因为表格有五行就断定有五个独立样本。

## 7.6 统计检验背后容易遗漏的判断

### 7.6.1 未拒绝原假设，为什么不能直接写“模型有效”

课件第 16、23 页分别检验总体均值是否等于给定基准，以及平均配对差是否为零。这两个假设检验采用的零假设都是“没有均值差异”。统计检验的逻辑并不是直接给“模型有效”打分，而是判断在零假设成立的条件下，当前观测到的样本差异是否过于罕见。

因此，可能出现两种截然不同的“不拒绝”。第一种是模型确实与现实较接近，而且样本量充足、区间很窄；第二种是模型与现实存在较大的偏差，但观测次数少、波动大，以至于检验没有足够的能力发现它们。普通的差异检验无法仅凭一个“不显著”区分这两种情形。

实际确认模型时，最好先由业务部门确定可接受的误差。例如，平均等待时间误差绝对值不超过 1 分钟是可以接受的。若记模型相对现实的均值偏差为：

```math
\Delta=\mu_{\mathrm{sim}}-\mu_{\mathrm{real}}
```

那么需要讨论的并不只是 `Δ=0` 能否被拒绝，而是有无足够证据使 `Δ` 落在业务可接受的范围内：

```math
-1<\Delta<1
```

对这种问题，更直接的思路是检查差值的置信区间是否足够窄，并使用适当的等效性检验。例如，在预先指定等效界值且满足对应假设时，可以使用两个单侧检验（TOST）方法；在 5% 显著性水平下，它与检查相应 90% 双侧置信区间是否完全落入等效界值内等价。这是对课件内容的统计学扩展，不是第七讲要求掌握的第三种确认方法。

考虑上面的配对例题。其 95% 差值置信区间为 `[-0.963,2.963]`。它虽然包含 0，却也包含大量业务上可能不可接受的偏差。假设容忍度是正负 1 分钟，我们当然不能说这一模型已经达到精度要求。

还有一个容易忽略的问题：即使平均数一致，两个系统的波动性也可能不同。某服务台的实际等待时间可能有严重长尾，而模型只生成围绕均值窄幅波动的数据。两者的平均等待时间差异检验可能不显著，但模型仍然不适合预测高峰时段的超长等待。

所以，检验平均值是重要证据，但应当与模型用途对应。用于容量规划的模型，除了均值，还可能需要确认高分位等待时间、排队长度、拥堵发生频率；用于生产排程的模型，还可能需要确认完工时间分布、设备利用率和在制品数量。

### 7.6.2 实际系统的基准值也有抽样误差怎么办

课件第一种方法把现实性能记为已知的 `μ₀`，然后对 `R` 次仿真运行均值做单样本 t 检验。但若所谓“实际平均等待时间 10 分钟”只是有限次现场观测的样本平均数，它同样存在抽样误差。此时直接把这个数字当成无误差常数，会低估比较的不确定性。

如果现场样本与仿真重复运行相互独立，并且已经分别构造出近似独立的性能指标样本，可以考虑对两个样本均值之差进行比较。记现场独立样本数为 `m`、样本方差为 `S_Z^2`，仿真独立重复次数为 `R`、样本方差为 `S_Y^2`，则均值差的估计标准误为：

```math
SE(\overline Z-\overline Y)
=\sqrt{\frac{S_Z^2}{m}+\frac{S_Y^2}{R}}
```

在常见的独立样本、方差不必相等的情形，可以采用 Welch 型 t 检验及其自由度近似。这一公式与前面的配对公式不冲突：若现场数据与仿真数据按相同历史输入成对出现，通常应优先利用配对差；若它们是两批互不对应的数据，才考虑独立两样本框架。不能把一批有时间相关性的现场逐秒数据简单视为无数个独立样本。

### 7.6.3 灵敏度分析应该检查“系统机理”，而不只是单调关系

课件第 10 页把灵敏度分析放在模型确认的第一步。通常做法是改变某一个输入或参数，检查输出变化的趋势。例如，提高服务能力，等待时间往往会下降；增加到达强度，在处理能力不变时，拥堵往往会加重。

但“往往”不是毫无条件的数学定理。若更改服务台数量的同时触发了新的分流规则、排班方式或顾客行为，某些输出可能出现非单调变化。因此，看到反常趋势时，应先识别该趋势是否违反模型已规定的机制，再判断是否需要修改模型。

为了减少随机波动对灵敏度判断的干扰，比较两个参数设置时，可使用第六讲讨论的公共随机数策略，让相同或可对应的外生随机因素尽可能一致。这样可以更容易判断输出差异究竟来自参数变化，还是来自两次仿真的随机抽样差异。

### 7.6.4 校准数据与确认数据为什么要分开

假设手头有 20 天真实生产记录。研究人员用前 15 天估计到达分布、服务时间分布，并反复调整模型直到这 15 天的平均等待时间完全匹配。此时只能说明模型对已经参与调节的数据拟合较好。要进一步判断模型能否描述未参与调节的实际情况，仍需要使用后 5 天或其他独立数据做确认。

一个清晰的流程是：

| 阶段 | 使用的数据 | 可进行的工作 | 不能据此宣称什么 |
| --- | --- | --- | --- |
| 输入建模 | 训练期原始到达和服务记录 | 估计分布、参数、输入相关结构 | 输入拟合好不等于输出符合现实 |
| 模型校准 | 训练期系统输出及业务规则 | 调整可解释的参数或结构假设 | 校准误差小不等于泛化能力好 |
| 模型确认 | 未参与校准的时间段或新场景 | 比较实际和仿真输出、做统计检验 | 未拒绝差异检验不等于所有用途均可信 |
| 应用与维护 | 后续运行记录 | 监测环境变化、重新评估模型适用性 | 过去通过确认不保证永久有效 |

如果真实系统的工艺或排班在前 15 天与后 5 天发生变化，也应将这种差异纳入分析。不能把所有时间上的变化都归因于模型失效；同时也不能因使用了“独立数据”四个字就忽略业务条件是否可比。

### 7.6.5 同一个案例：为什么“程序正确”不代表“模型符合现实”

设现实车间有两类订单：普通订单与加急订单。现场规则是加急订单可以优先进入下一工序，设备还会按排班计划停机。建模人员却将所有订单合并为一条 FCFS 队列，而且没有设置设备停机事件。

程序可能完全按 FCFS 的逻辑执行，事件列表、资源状态、顾客计数都不出错。按照第 7.1 节的标准，它的程序验证甚至可能很完善。然而，若研究问题是评估“加急订单承诺交期”，这个模型显然缺少关键业务机制。即使通过调整平均服务时间，把全体订单的平均周转时间调得与历史数据很接近，也无法弥补优先级机制缺失的问题。

这一情形可以明确区分三件事：

| 活动 | 在该案例中回答的问题 |
| --- | --- |
| 验证 Verification | FCFS 逻辑是否被程序正确执行，状态统计是否算对 |
| 校准 Calibration | 调整哪些参数可以改善模型对已知历史数据的拟合 |
| 确认 Validation | 对于加急订单交期这一研究用途，模型结构与输出是否足以代表实际车间 |

第三件事不能被前两件事替代。若模型用于描述全体订单的粗略平均负荷，部分简化可能尚可接受；若模型用于评估加急订单服务水平，则同样的简化可能不可接受。模型确认始终与<strong>明确的研究目的和适用范围</strong>联系在一起。

## 7.7 考试中怎样判断属于哪一种问题

### 7.7.1 方法选择表

| 题目给出的信息 | 应优先判断为 | 关键动作 |
| --- | --- | --- |
| 有主程序、子程序、事件表，要找状态逻辑错误 | 程序验证 | 对照事件规则、状态守恒、追踪运行过程 |
| 给出模型结构和现实业务流程，要求指出简化是否合理 | 模型确认中的假设检查 | 检查结构假设与数据假设 |
| 改变到达率、服务台数，判断输出变化趋势 | 模型确认中的直观有效性检查 | 解释变化方向是否符合机制 |
| 给出一个实际系统基准 `μ₀` 和 `R` 次独立仿真均值 | 使用拟合分布的第一种统计确认方法 | 对 `R` 个运行均值做单样本 t 检验 |
| 给出同一批历史输入下实际—仿真成对数据，共 `k` 组 | 使用历史数据的第二种统计确认方法 | 先算 `k` 个差值，再做配对 t 检验 |
| 实际基准也仅由一批独立现场样本估计得到 | 第一种方法之外的扩展情形 | 考虑现场与仿真两侧的抽样不确定性 |
| 输出差异检验不显著，问能否直接确认模型有效 | 统计推断的解释题 | 不能直接认定；须考虑区间宽度、业务误差界值和研究用途 |

### 7.7.2 两类 t 检验最容易混淆的地方

| 项目 | 第一种方法：单样本 t 检验 | 第二种方法：配对 t 检验 |
| --- | --- | --- |
| 比较对象 | 多次仿真均值与固定现实基准 | 同一历史输入下的现实—仿真差值 |
| 构造的统计样本 | `Ȳ₁,...,Ȳᵣ,...,Ȳᴿ` | `d₁,...,dₖ` |
| 样本量 | `R` | `k` |
| 样本标准差 | `S`：运行均值的标准差 | `S_d`：配对差的标准差 |
| 分母 | `S/√R` | `S_d/√k` |
| 分子 | `Ȳ−μ₀` | `d̄−0` |
| 自由度 | `R−1` | `k−1` |

记忆方法不必死背两套表面不同的公式。两种方法实质上都是把“样本均值与原假设下的数值之差”除以对应的标准误：

```math
t=\frac{\text{sample mean}-\text{null value}}
{\text{standard error of sample mean}}
```

不过，GitHub 数学公式渲染的英文占位符只是帮助识别结构。真正解题时，要先建立正确的数据列：单样本方法用每次独立运行均值，配对方法用每一对实际—仿真差值。把样本构造正确，统计公式才能正确。

### 7.7.3 自测题与参考判断

<strong>题目一。</strong>仿真程序可以正常运行，所有资源利用率都在 0 与 1 之间，是否说明模型已经得到确认？

参考判断：不能。最多说明这些输出没有违反最基本的数值边界；程序的逻辑验证还需要事件测试，而模型是否能够代表现实需要检查结构、数据假设与实际输出。

<strong>题目二。</strong>某模型使用理论分布生成随机输入，重复运行 12 次，实际系统给出一个已知平均响应基准。应该使用哪一种检验，自由度是多少？

参考判断：若这 12 次运行彼此独立且相应近似条件成立，使用单样本 t 检验，自由度为 11。不能把 12 次运行中所有单个顾客直接当成独立重复次数。

<strong>题目三。</strong>实际系统与仿真模型用 8 组一一对应的历史输入，并得到 8 对响应均值，应如何检验？

参考判断：先对每组求 `d_j=Z_j-Y_j`，再对 8 个差值做配对 t 检验，自由度是 7。需要核实 8 组之间是否近似独立。

<strong>题目四。</strong>某次检验得到 `p=0.38`，能否写“以 95% 的概率证明了模型有效”？

参考判断：不能。p 值不是原假设成立的概率；检验未发现显著差异也不等于证明了模型与真实系统相同。需要结合置信区间、样本量和实际可接受偏差。

<strong>题目五。</strong>建模人员使用同一批 30 天历史数据估计输入分布、调整模型参数，再用同一批数据报告确认误差极小，有什么问题？

参考判断：这是在参与校准的数据上评价模型，可能高估模型在新时段、新工况中的表现。应预留不参与模型调整的确认数据，或者另行收集独立场景数据。

<strong>题目六。</strong>模型输出平均等待时间与现实平均等待时间非常接近，就一定能正确评估极端拥堵吗？

参考判断：不一定。平均数相近并不能保证方差、分位数、尾部和动态过程相同。若应用目标是高峰排队风险，应检查对应的尾部绩效与时间变化。

<strong>题目七。</strong>若现实系统无法获取足够的历史记录，第七讲建议完全停止仿真建模吗？

参考判断：不是。课件第 24 页要求尽量完善程序验证，并听取熟悉业务的专家判断。但应把数据缺失导致的确认局限记录清楚，不宜把专家判断替代为已经完成统计确认。

## 7.8 本讲公式索引与使用顺序

本讲涉及的计算可以整理为两个模板，二者都遵循“明确样本—计算均值—计算样本方差—计算标准误—计算 t 值—判断”的顺序。

<strong>模板一：现实基准视为已知常数。</strong>

```math
\overline Y=\frac{1}{R}\sum_{r=1}^{R}\overline Y_r,
\qquad
S^2=\frac{1}{R-1}\sum_{r=1}^{R}
(\overline Y_r-\overline Y)^2
```

```math
t=\frac{\overline Y-\mu_0}{S/\sqrt R},
\qquad df=R-1
```

<strong>模板二：现实与仿真成对比较。</strong>

```math
d_j=Z_j-Y_j,
\qquad
\overline d=\frac{1}{k}\sum_{j=1}^{k}d_j
```

```math
S_d^2=\frac{1}{k-1}\sum_{j=1}^{k}(d_j-\overline d)^2
```

```math
t=\frac{\overline d}{S_d/\sqrt k},
\qquad df=k-1
```

如果题目没有让你计算统计量，而是要求解释如何验证或确认模型，就回到前面的工作流程：验证查看代码是否按规则运行，确认查看结构、数据和输出是否足以代表现实。此时继续堆叠统计公式反而不能回答题目的核心。

## 7.9 统计上没有显著差异，究竟能否说明模型足够准确？

第七讲的单样本和配对 `t` 检验，都是从“实际与仿真在均值上没有差别”的原假设出发。如果检验得到 `p>0.05`，只能表述为现有数据<strong>不足以否定均值相等</strong>。模型偏差很小和样本量太少，都可能出现这一结果。对于需要决定模型能否交付使用的管理问题，更直接的问题往往是：<strong>模型偏差是否小到可以接受？</strong>

### 7.9.1 先定义允许误差，而不是做完检验后再改标准

例如，一个排队仿真模型用于预测平均等待时间。业务部门事先规定：仿真与现实的总体平均等待时间相差不超过 1 分钟，就足以支持当前服务台配置决策。记配对差总体均值为 `μ_d`，设可接受误差为 `Δ=1` 分钟，则关心的是：

```math
-\Delta<\mu_d<\Delta
```

这与第七讲通常的“检验是否正好等于零”是不同的问题。实际系统很少要求模型输出与现实完全相同；关键是偏差能否小到不影响具体决策。这里的 `Δ` 必须根据业务容忍度在看结果前确定，不能先看出差值再把阈值调大。

### 7.9.2 一组完整数据：等效性判断怎样做

设六组互不重叠的历史场景形成的实际—仿真配对差（单位：分钟）为：

| 场景 | 1 | 2 | 3 | 4 | 5 | 6 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 实际值减仿真值 `dⱼ` | −0.8 | −0.4 | 0 | 0.2 | 0.4 | 0.6 |

先依照前面配对检验的步骤计算均值与样本方差：

```math
\begin{aligned}
\overline d&=\frac{-0.8-0.4+0+0.2+0.4+0.6}{6}=0,\\
S_d^2&=\frac{1.36}{6-1}=0.272,\\
S_d&=\sqrt{0.272}\approx0.5215,\\
SE(\overline d)&=\frac{0.5215}{\sqrt6}\approx0.2129
\end{aligned}
```

假定各对差值可以近似独立同分布且符合 `t` 区间的适用条件。已知 `t_{0.975}(5)=2.571`，普通双侧 95% 置信区间为：

```math
0\pm2.571(0.2129)\approx[-0.547,\;0.547]
```

它包含零，因此常规双侧检验不会拒绝“均值差为零”。但本题真正要判断的是容忍区间 `(-1,1)`。采用显著性水平 0.05 的双单侧等效性检验（TOST），等价的区间判据是检查<strong>90% 双侧置信区间是否完全落入容忍区间</strong>。已知 `t_{0.95}(5)=2.015`，计算：

```math
CI_{90\%}=0\pm2.015(0.2129)
\approx[-0.429,\;0.429]
```

由于 `[-0.429,0.429]` 完全位于 `(-1,1)` 内，可以在上述统计假设下，认为该指标的平均偏差满足预先规定的等效性要求。注意等效性成立只针对当前这一个平均等待时间指标，不意味着模型对高分位等待时间、拥堵峰值、其他服务策略也准确。

这部分是第七讲模型确认逻辑的<strong>延伸方法</strong>，不是声称原课件要求掌握 TOST。考试若只要求按课件做配对 `t` 检验，仍按第 7.3、7.5 节给出的原方法计算。

## 7.10 实际数据和仿真数据并不配对时，应该怎样比较均值

前文讨论了两种课件方法：把现实基准视为一个已知常数时，使用单样本检验；实际与仿真共用同一组历史输入时，对每组差值做配对检验。但实际研究中还有第三种数据结构：<strong>双方分别收集了独立样本，既没有一个完全已知的现实均值，也没有一一对应的场景。</strong>

例如，现场随机抽取四个相互独立的工作日，平均等待时间为 `5、6、7、6` 分钟；仿真模型另外独立重复四次，各次平均等待时间为 `5、5、6、6` 分钟。两边没有按相同场景逐一对应，因而不能人为把第一项与第一项相减来做配对检验。

现场和仿真的样本均值、无偏样本方差分别为：

```math
\begin{aligned}
\overline Z&=6,&S_Z^2&=\frac{2}{3},\\
\overline Y&=5.5,&S_Y^2&=\frac{1}{3}
\end{aligned}
```

如果假设两组的观测独立、组内可近似使用 `t` 方法，且不强制两组方差相等，可以用 Welch 两独立样本统计量：

```math
\begin{aligned}
SE(\overline Z-\overline Y)
&=\sqrt{\frac{S_Z^2}{4}+\frac{S_Y^2}{4}}=0.5,\\
t&=\frac{6-5.5}{0.5}=1
\end{aligned}
```

其自由度需要用 Welch–Satterthwaite 公式近似，而不是直接写成 `4-1=3` 或 `4+4-2=6`：

```math
\nu\approx
\frac{\left(S_Z^2/4+S_Y^2/4\right)^2}
{\dfrac{(S_Z^2/4)^2}{4-1}
+\dfrac{(S_Y^2/4)^2}{4-1}}
\approx5.4
```

这个 `t=1` 在常见的双侧 5% 显著性水平下不足以拒绝均值相等。计算示例只说明<strong>统计方法由样本对应关系决定</strong>；四个工作日是否真正相互独立、现场与模拟是否处于相同工况，仍需在建模时核查。

考试选择检验方法时，可以先问三句：现实值是否被题目明确当作已知常数？现实与模拟是否一一配对？如果两个答案都是否，才考虑独立两样本比较。本节也是原课件两种确认方法之外的补充，避免把课件里的配对公式用于不配对数据。

## 7.11 不依靠统计检验的程序核验：用事件守恒发现模型错误

模型确认讨论的是“像不像现实”，但仿真程序自身还必须满足业务流程的基本守恒关系。这些关系通常比比较一个最终均值更容易发现事件调度的错误。以单服务台、先到先服务、无中途离开且不丢单的系统为例，有：

```math
N(t)=N(0)+A(t)-D(t)
```

其中 `A(t)` 是累计到达数，`D(t)` 是累计完成并离开系统的数量，`N(t)` 是系统内人数（包括正在服务者）。同一个顾客的进入、出队、服务开始和离开必须对应；如果某一步出现 `N(t)<0`，或无顾客仍触发正常服务完成，那么程序逻辑就出了问题。

### 7.11.1 手工核验一组完整事件

假设三个顾客按 A、B、C 的顺序分别在 `t=0、1、2` 到达，服务时长分别是 `3、2、1`，服务台初始空闲。约定服务结束后立即让队首顾客开始服务。

| 时刻 | 事件与下一步动作 | 等待队列 | 正在服务 | 系统内人数 |
| ---: | --- | --- | --- | ---: |
| 0 | A 到达，立即服务，预计 3 完成 | 空 | A | 1 |
| 1 | B 到达，服务台繁忙，进入队列 | B | A | 2 |
| 2 | C 到达，排在 B 后面 | B、C | A | 3 |
| 3 | A 完成离开，B 开始服务，预计 5 完成 | C | B | 2 |
| 5 | B 完成离开，C 开始服务，预计 6 完成 | 空 | C | 1 |
| 6 | C 完成离开 | 空 | 空 | 0 |

三个顾客等待时间分别为 `0、2、3`，故平均等待时间是：

```math
\overline W_q=\frac{0+2+3}{3}=\frac{5}{3}
```

结果的单位与到达、服务时长使用的时间单位相同。

如果将“等待队列人数”记为 `Q(t)`，整个 `[0,6]` 期间的队长—时间面积为：

```math
\begin{aligned}
\int_0^6Q(t)\,dt
&=1(2-1)+2(3-2)+1(5-3)\\
&=1+2+2=5
\end{aligned}
```

注意这恰好等于三个顾客等待时间之和 `0+2+3=5`。这是因为<strong>完整观察了所有顾客从到达到离开队列的等待区间</strong>，每个等待者在队列人数曲线下都贡献了与其等待长度相等的面积。如果在最后一个顾客仍在排队时截断观察，就不能忽略截尾后尚未完成的等待部分。

本例还提供三个相互独立的核查角度：事件表中的人数守恒、每位顾客的等待时间、队长曲线的面积。若程序给出的平均等待时间与手算不一致，可以逐时刻追踪哪次到达、开始服务或离队事件被漏记或重复计算。这个核验属于 <strong>Verification</strong>；即便三项完全正确，也仍需检查模型的服务规则和输入分布能否代表真实业务，才能讨论 <strong>Validation</strong>。
