# 第七讲｜仿真模型的验证与确认

本讲依据课程课件 `simulation7_v3.pdf`（24 页），依次讲解 7.1 仿真模型的验证、7.2 仿真模型确认的“三步法”和 7.3 仿真输出数据与实际数据的比较方法。

## 先区分两个概念：Verification 与 Validation（课件第 1—2 页）

一个仿真模型运行正常，甚至能生成很多看似合理的数据，并不意味着它能够代表实际系统。评价模型时，首先需要区分两个不同的问题。

| 概念 | 中文名称 | 要回答的问题 | 主要检查对象 |
| --- | --- | --- | --- |
| Verification | 验证 | 仿真程序有没有正确执行已经规定的模型逻辑？ | 程序实现、事件规则、状态更新、计算过程 |
| Validation | 确认 | 所建立的模型能否足够准确地描述现实系统？ | 模型结构、假设、输入数据、输出与实际的差异 |

例如，为一个单服务台系统编写仿真程序。程序能够按到达顺序分配服务、正确更新等待队列，说明程序的逻辑可能通过了验证。但是，如果现实中存在优先级插队，而模型始终采用先到先服务，那么程序即使完全没有错误，模型也未必得到确认。

两者的先后关系是：先检查程序是否正确实现模型，再检查这个模型是否足以代表现实。不过，在建模过程中它们可以反复进行，而不是只能各做一次。

## 7.1 仿真模型的验证（课件第 3—8 页）

验证的目标是检查仿真程序的逻辑正确性，发现并排除实现过程中的问题。课件列出五项工作。

### 7.1.1 使用子程序编写与调试

课件第 4 页强调由简到繁、逐步深入。不要在所有模块尚未检查的情况下，就把一个复杂系统整体运行并仅凭最终结果判断程序是否正确。

具体来说，可以先确认主程序和关键子程序的基本规则是否正确，再逐步加入其他功能。例如，对于离散事件仿真，可以先检查到达事件与服务完成事件是否能按时间推进，再检查等待队列、服务台状态以及统计量的更新。

这样分步调试的原因，是每次只增加少量逻辑。如果新增一个模块后结果出现异常，就能将检查范围缩小到最近新增的部分。

这里所说的子程序不一定是某种特定编程语言的函数；在 Arena 等图形化仿真软件中，也可以把它理解为能够单独检查的流程段或模块组合。

### 7.1.2 检查主要参数的输出

课件第 5 页要求，在仿真运行中检查主要输出及其响应是否合理，特别提到设备利用、排队情况和系统内实体数量的变化。

以排队系统为例，不能只检查最后得到的平均等待时间，还应同时观察：

| 观察量 | 应当检查什么 |
| --- | --- |
| 服务台利用情况 | 服务台何时忙碌、何时空闲，是否符合加工过程 |
| 等待队列 | 顾客到达、开始服务、离开队列时，队长是否正确变化 |
| 系统内实体数 | 到达增加实体、离开减少实体，人数变化是否前后一致 |
| 参数改变后的输出 | 到达量、处理能力等主要参数变化时，模型响应是否符合预期逻辑 |

这里的“合理”首先是程序层面的检查。例如，同一个顾客不能同时占用两台互斥服务设备；如果没有顾客到达，模型不应凭空增加正在服务的顾客。

### 7.1.3 运行时跟踪检查（Trace）

课件第 6 页要求追踪系统状态和参数的动态变化过程，而不只是检查仿真结束后的汇总表。许多仿真语言都提供事件或状态跟踪功能。

对于事件驱动系统，跟踪记录可以按事件顺序写成：

| 检查项目 | 记录的内容 |
| --- | --- |
| 当前仿真时刻 | 事件发生的时刻与推进顺序 |
| 当前事件 | 到达、开始服务、服务完成等 |
| 资源状态 | 忙碌或空闲，以及正在服务的实体 |
| 队列状态 | 队列中的人数和排列顺序 |
| 系统状态 | 系统内实体总数及其增减 |

课件给出的典型逻辑错误是“系统中有顾客而服务台却空闲”。对一个顾客可立即占用空闲服务台的普通队列模型，这通常说明事件规则或队列分配存在问题。但判断时仍应结合模型规定的服务资格、停机状态或其他限制，不能把所有空闲一概视为错误。

跟踪检查的操作要点是：找到出现异常的第一个事件时刻，再检查该事件之前与之后的状态更新。这样通常比从最终平均数倒推错误更直接。

### 7.1.4 分类测试

课件第 7 页把测试分为四类，每一类检查的重点不同。

| 测试类型 | 课件要求 | 主要检查目的 |
| --- | --- | --- |
| 基本测试 | 跟踪单一实体，使用常量数据，改变各种参数 | 用容易手算的数据检查最基本的执行规则 |
| 情景测试 | 使用不同输入数据进行长时间运行 | 观察超长队列、资源长时间闲置等异常情形 |
| 极端情况测试 | 让系统在超负荷等极端条件下运行 | 检查边界状态与压力状态下的模型逻辑 |
| 动态行为测试 | 利用动画观察运行过程 | 检查实体移动、资源占用与流程转换是否符合模型规定 |

基本测试中使用常量数据尤其重要。例如，固定所有到达间隔与服务时间后，随机波动被排除，可以逐项手算顾客的到达、开始服务和完成服务时刻，再与程序输出对照。

情景测试和极端情况测试并不要求模型始终显示“好”的绩效。若系统处理能力明显不足，出现不断累积的队列本身可能是正确结果；需要检查的是队列增长的机制有没有按规则执行，以及程序能否正确处理这种状态。

动态行为测试所用动画也不只是展示效果。若观察到实体穿过不该经过的工序，或资源尚未释放便开始处理另一项互斥任务，这些现象可以直接提示程序逻辑问题。

### 7.1.5 验证活动的验收

课件第 8 页提出，验证活动及其结论应通过客户小组会等方式获得客户认可。

验收时需要说明检查了哪些模块、使用了什么测试情景、发现并修复了什么问题，以及目前的验证结论。客户的认可意味着相关方接受这一轮程序验证活动，并不自动证明模型对现实系统的描述已经准确。后一问题仍属于模型确认的范围。

## 7.2 仿真模型的确认：“三步法”（课件第 9—12 页）

模型确认并不是检查程序是否报错，而是反复比较仿真模型与实际系统，并利用差异调整模型，使其对实际系统的描述更加准确。课件把确认过程概括为三个步骤。

### 7.2.1 第一步：直观考察模型的有效性

课件第 10 页强调两个方面：直观合理性和灵敏度分析。

所谓直观合理性，是让了解实际系统的使用者参与判断。模型中有哪些实体、资源、业务规则和限制条件，事件发生的先后关系是什么，这些内容应能让熟悉业务的人理解，并且与其经验相符。

灵敏度分析则是主动改变输入或模型参数，观察输出变化的方向与趋势是否合理。例如，在其他条件相同的前提下，提高服务能力后，如果模型反而持续出现更长的等待队列，就需要检查发生这种变化的机制。这里关注的不只是某个数值是否相等，而是输入与输出之间的反应关系是否符合系统机理。

这一步能够发现明显不合理的结构或响应，但不能单凭“看起来像”就断定模型有效。因此还需要后两步。

### 7.2.2 第二步：检验模型假设

课件将模型假设分为两类。

结构假设（Structural Assumptions）来自对实际系统的简化和抽象。例如，是否将若干服务环节合并为一个环节，是否忽略某些资源约束，是否假设所有顾客都按相同规则排队。检查这些假设时，应判断简化是否保留了影响研究结果的关键机制。

数据假设（Data Assumptions）指输入数据的数值或概率分布。例如，到达间隔与服务时间采用什么分布，分布参数取什么值，输入样本是否能够代表真实业务情境。即使模型结构正确，错误的数据假设仍可能导致不可信的仿真输出。

这里要区分两种不同的错误：结构假设不合适，通常需要修改系统逻辑；数据假设不合适，通常需要重新检查实际样本、参数估计或输入分布。二者并不总能通过调整某一个参数互相弥补。

### 7.2.3 第三步：比较模型输出与实际数据

课件第 12 页建议充分利用现有系统的历史数据。通常将一组历史数据用于模型校准（Calibration），另一组数据用于模型确认（Validation）。

校准的作用是根据实际数据调整模型，使它更好地符合已知系统；确认则是用另一组数据检查调整后的模型是否仍能有效反映实际系统。如果始终在同一组数据上修改模型并评价模型，就难以判断它能否代表未参与校准的实际情形。

如果现实中的完整系统与拟建模型不完全相同，但二者具有大量相同子系统，课件建议先针对这些子系统建立模型并分别确认，再进行组合。这样可以先确认已经能够观察和比较的部分，再逐步处理整体系统的差异。

第 7.3 节给出比较模型输出与实际数据的两种具体统计方法。

## 7.3 仿真输出数据与实际数据的比较方法（课件第 13—24 页）

### 7.3.1 方法一：使用拟合输入数据的理论分布进行确认

课件第 14 页首先指出一个基本前提：实际系统与仿真模型必须在类似的输入条件下进行比较。如果两边面对的输入条件不同，即使最终输出存在差异，也难以判断差异是模型造成的，还是输入条件造成的。

因此，比较时先固定一组决策变量，即模型中可控制的设置。课件用排队系统举例，决策变量可以是服务台数量、队列数量、排队规则等。然后让实际系统按客观发生的过程运行，让仿真模型按拟合的输入概率分布运行，选择一个主要性能指标作为确认准则。

假设实际系统这一性能指标的基准值为 `μ₀`。对仿真模型进行 `R` 次独立重复运行，每次记录 `n` 个输出。记第 `r` 次运行中第 `i` 个输出为 `Yᵣᵢ`。

第一步，计算各次独立运行的均值：

```math
\overline Y_r=\frac{1}{n}\sum_{i=1}^{n}Y_{ri},
\qquad r=1,2,\ldots,R
```

第二步，计算 `R` 个运行均值的总平均：

```math
\overline Y=\frac{1}{R}\sum_{r=1}^{R}\overline Y_r
```

第三步，计算各次运行均值之间的样本方差和标准差：

```math
S^2=\frac{1}{R-1}\sum_{r=1}^{R}
(\overline Y_r-\overline Y)^2,
\qquad S=\sqrt{S^2}
```

课件第 16 页建立原假设：

```math
H_0:E(Y)=\mu_0
```

这表示仿真输出的总体均值与实际系统基准值一致。进行双侧检验时，与之对应的备择假设是：

```math
H_1:E(Y)\ne\mu_0
```

当单次运行的观测量 `n` 足够大时，各次运行均值可以近似服从正态分布；每次重复使用独立的随机数流，因而这些运行均值可以近似看作相互独立。在这样的条件下，使用单样本 `t` 统计量：

```math
\boxed{
t=\frac{\overline Y-\mu_0}{S/\sqrt R}
}
```

在原假设成立且相应正态近似适用时，统计量近似服从自由度为 `R−1` 的 `t` 分布：

```math
t\sim t_{R-1}
```

给定显著性水平 `α`，双侧检验的判定规则为：

```math
\boxed{
|t|>t_{1-\alpha/2}(R-1)
}
```

也就是说，将仿真均值与实际基准之间的差额，除以仿真运行均值的标准误。如果这一标准化差异的绝对值超过临界值，就认为两者的均值存在统计上显著的差异。

反过来，未达到拒绝条件只能说明当前样本没有提供足够证据认定两者不同，不等于证明两者完全相同。还应结合实际业务对误差大小的要求判断模型能否接受。

注意：课件把 `μ₀` 作为已给定的实际性能基准，因此使用上述单样本检验；如果 `μ₀` 本身也只是有较大抽样误差的估计值，这个公式就没有包含实际基准的不确定性，不能不加检查地照搬。

### 7.3.2 方法二：直接使用历史输入数据进行确认

与上一种方法不同，课件第 20 页的第二种方法不再让仿真模型仅依照拟合的理论分布自行产生输入，而是将实际系统记录的输入数据保存到数组或文件中，并在仿真运行时将这些真实历史输入逐组调入模型。

例如，把某段历史中的实际到达间隔、实际服务时间等输入序列交给仿真模型，使实际系统与仿真模型面对同一组输入条件，再比较双方的输出。这种比较建立在对应关系上，因此要使用配对（匹配）检验。

假设共收集 `k` 组历史输入数据，并以它们分别进行同步仿真。对第 `j` 组输入：

`Zⱼ` 表示实际系统对应该组输入的响应样本均值；`Yⱼ` 表示仿真模型对应该组输入的响应样本均值。二者必须是同一项性能指标，具有相同的计量单位。

第一步，对每组历史输入计算一对实际—仿真的差值：

```math
d_j=Z_j-Y_j,
\qquad j=1,2,\ldots,k
```

第二步，计算这 `k` 个配对差的样本均值：

```math
\overline d=\frac{1}{k}\sum_{j=1}^{k}d_j
```

第三步，计算配对差的样本方差与标准差：

```math
S_d^2=\frac{1}{k-1}\sum_{j=1}^{k}
(d_j-\overline d)^2,
\qquad S_d=\sqrt{S_d^2}
```

设配对差的总体均值为 `μ_d=E(d_j)`，课件第 23 页提出：

```math
H_0:\mu_d=0,
\qquad H_1:\mu_d\ne0
```

如果原假设成立，意味着实际系统与仿真模型的平均配对差为零。采用配对 `t` 统计量：

```math
\boxed{
t=\frac{\overline d}{S_d/\sqrt k}
}
```

在适用条件下，其分布近似为：

```math
t\sim t_{k-1}
```

双侧检验的拒绝域是：

```math
\boxed{
|t|>t_{1-\alpha/2}(k-1)
}
```

### 7.3.3 为什么要对差值检验，而不是把两组结果拆开检验

实际系统的第 `j` 个输出均值 `Zⱼ` 与仿真模型的第 `j` 个输出均值 `Yⱼ`，来自同一组历史输入，因此存在明确的一一对应关系。把它们相减，可以使两边共同面对的输入波动在差值中部分抵消。此时真正用于统计检验的样本是：

```math
d_1,d_2,\ldots,d_k
```

课件第 22 页说明了使用配对 `t` 检验的三个统计理由。

第一，各组输入都来自所研究的同一系统，因此相应差值可以近似视为同分布。

第二，如果这 `k` 组历史输入在时间上没有重叠，并且组间不存在其他显著依赖关系，可以将各组差值近似视为独立。

第三，`Zⱼ` 与 `Yⱼ` 本身都是相应一组数据的样本均值；每组包含足够多观测时，可采用正态近似，继而对差值使用 `t` 检验。

因此，这里自由度是 `k−1`，不是实际系统与仿真系统观测总数减一。配对检验利用的是每组输入下“两边差多少”，而不是把所有实际输出和所有仿真输出当成互不相关的两批数据。

### 7.3.4 两种确认方法的区别

| 比较内容 | 使用拟合输入的理论分布 | 使用历史输入数据 |
| --- | --- | --- |
| 仿真输入 | 由拟合后的概率分布生成 | 将记录的实际历史输入交给模型 |
| 实际系统数据 | 一个性能指标的实际基准 `μ₀` | 每组历史输入对应的实际输出均值 `Zⱼ` |
| 仿真数据 | `R` 次独立运行的均值 `Ȳᵣ` | 与实际数据成对的 `k` 个仿真输出均值 `Yⱼ` |
| 检验对象 | 仿真总体均值是否等于 `μ₀` | 实际—仿真配对差的总体均值是否为零 |
| 统计方法 | 单样本 `t` 检验 | 配对 `t` 检验 |
| 自由度 | `R−1` | `k−1` |

两种方法的目的相同，都是检查模型输出是否与现实相符；差异在于如何构造具有可比性的输入与输出，以及最后把什么量当作统计样本。

### 7.3.5 使用历史数据时的注意事项（课件第 24 页）

课件最后强调，首先必须核对历史数据的真正含义。例如，企业系统中用于会计或计划的标准作业时间，不一定是车间现场实际发生的加工时间。如果将标准数据误当作真实运行数据，再用它们确认仿真模型，就可能得到没有实际说服力的结论。

其次，在现场数据缺失或其他条件限制下，如果暂时无法直接确认模型，应尽可能做好程序验证，并请最熟悉实际系统的人员判断模型的结构、规则和输出是否合理。这可以为模型可信度提供部分依据，但应明确哪些方面尚未得到实际数据的直接确认。
