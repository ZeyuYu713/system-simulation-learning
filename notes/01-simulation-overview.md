# 第一讲｜仿真概述

[返回学习目录](../README.md) · [相关专题：随机数与随机变量](01-random-numbers.md)

本讲对应课程课件 `simulation1_v3.pdf`（35 页）。课件从项目工期和银行服务的实际问题出发，依次介绍仿真的定义、优缺点、适用条件、模型分类、实施手段与步骤，以及发展和应用领域。本笔记按照 1.1—1.10 的原有顺序展开。

## 1.1 引例：为什么需要仿真？（课件第 3—10 页）

课件先提出两个管理问题：一个工程项目能否在截止日期前完工，一家银行应当如何配置服务资源。这两个问题的共同点是：管理者最终关心的是系统运行的结果，而这个结果既受到业务流程的约束，又可能受到随机因素影响。

### 1.1.1 项目管理：44 周与 84% 不是同一个结论

课件第 4—5 页给出从 START 到 FINISH 的工程活动网络，活动代号为 A—N，包含开挖、地基、墙体、屋顶、管道、电气施工、地板、室内外装修及设施安装等工作。不同活动之间存在先后关系，一些工作能够并行进行，另一些工作必须等待前置工作结束。

课件展示了两个结果：

| 课件给定结果 | 表示什么 | 不能直接推出什么 |
| --- | --- | --- |
| 项目工期为 44 周 | 在图示活动时间和前后关系下计算得到的进度结果 | 不能保证实际施工一定在 44 周结束 |
| 47 周内完工的概率为 0.84 | 在课件所用随机条件或分析设定下，按期完工的概率为 84% | 不能认为每一次项目实施都会在 47 周内完成 |

用随机变量表示实际完工时刻，可以把后一结论写成：

```math
P(T\leq 47)=0.84
```

其中，`T` 表示项目的实际完工时间，单位为周。这里的 `0.84` 是课件给出的数值，并非仅凭第 4—5 页的活动网络就能独立复算出的概率；要计算它，还需要了解各项任务工期如何变化、采用什么随机模型以及如何统计多次结果。

为什么有了 44 周的工期还要关心概率？因为计划进度是按一组活动工期得到的，而实际施工会受到材料供应、返工、设备故障等不确定因素影响。一个看起来具有三周余量的项目，仍可能发生延期。如果决策问题是“要不要向业主承诺 47 周交付”，那么仅报告 44 周不足以描述交付风险。

仿真在这一问题中的作用，是按照活动之间的约束关系，给可能变化的活动时间提供输入，在不同实现中计算项目完成时间，再依据多次运行结果分析完工时间分布及延期风险。项目网络负责表达施工逻辑，随机输入负责表达不确定性，输出分析负责回答交付概率；三者不能相互替代。

### 1.1.2 银行运作：最佳配置不等于最短队列

课件第 6 页提出“如何确定最佳配置”。对银行而言，配置问题可以表现为设置多少服务窗口、安排多少工作人员，以及不同业务如何进入服务流程。

只增加服务窗口，通常有机会缓解排队，却也增加资源使用成本；只减少窗口，可能节约人员投入，却会加重高峰期等待。因此，“最佳”需要先明确衡量标准，例如等待时间、队列长度、服务台利用程度以及资源投入。课件没有给出这道银行题的具体数据或最优窗口数量，不能自行认定某一个配置方案是最优解。

通过仿真，可以对若干候选配置采用相同的业务假设进行实验，比较各方案下顾客等待、资源忙闲和系统运行状况。要得到可信的比较，仍然需要对顾客到达情况、服务时间和业务规则进行合理建模。

### 1.1.3 模拟结果为什么会受到质疑？

课件第 7—8 页连续追问：结果是否可信、如何得出、使用了什么数据、数据怎样生成、输入能否反映实际情况、模型是否描述真实运行、结果能否支持现实决策。这些质疑说明，一组仿真输出不是天然成立的事实。它首先是某个模型在给定输入与假设下产生的结果。

课件第 9—10 页据此引出全课程的知识结构：

| 要回答的问题 | 对应的课程内容 |
| --- | --- |
| 计算机生成的随机数据是否正确？ | 随机数与随机变量的生成 |
| 实际系统的输入有什么统计特性？ | 仿真输入分析 |
| 怎样依据运行输出判断系统性能？ | 仿真输出分析 |
| 模型或程序是否可信、是否可用？ | 仿真模型的验证与确认 |
| 系统怎样表达、推进和求解？ | 仿真原理及仿真建模与求解 |
| 怎样在候选方案中寻找更好的决策？ | 仿真优化基础 |

这些问题也解释了为什么本课程不仅要学习仿真软件操作，还要学习概率统计、事件逻辑、实验设计以及模型可靠性检查。软件可以执行模型，却不能自动保证模型的输入、结构与结论都正确。

## 1.2 什么是仿真？（课件第 11—12 页）

课件将仿真理解为：以系统理论、形式化理论、概率与随机过程、统计理论及优化理论等为基础，借助计算机和仿真软件，对实际系统的行为进行动态实验研究，并据此估计实际系统性能的方法。

这一表述涉及三个不同对象：

| 对象 | 在仿真研究中承担的任务 |
| --- | --- |
| 实际系统 | 研究对象，例如银行营业网点、施工项目或生产车间 |
| 仿真模型 | 按研究目的保留系统中的关键实体、活动、状态及规则 |
| 计算机与仿真软件 | 按既定逻辑运行模型，记录数据并形成可供分析的输出 |

研究路径可以理解为：先观察实际系统并决定哪些机制需要纳入模型，再通过计算机执行模型实验，最后使用输出结果估计真实系统的相关性能。模型不是现实系统的完整复制品；它必须围绕具体问题作取舍。例如研究银行等待时间时，顾客到达、服务时间和窗口配置很重要，但营业厅装修颜色通常不会进入模型。

仿真的“实验”与普通静态计算有区别。静态计算可能只求一次给定条件下的结果，而动态仿真关注状态随过程怎样变化：什么时候有人到达、何时进入队列、何时开始接受服务，以及离开后资源如何释放。管理者研究的是整个系统在一段运行过程中的行为，而不只是孤立的某个数字。

仿真不等同于真实系统的现场实验。真实实验直接改变实际业务；仿真实验是在模型中修改条件、运行和观察，因而可以反复比较多种情景。

## 1.3 仿真的优点与缺点（课件第 13—14 页）

### 1.3.1 优点：可在模型中反复试验系统行为

课件列出的优点包括可控、无破坏、可复现和经济。在模型中调整到达频率、设备数量或工作流程，不必先改变实际营业网点或生产线。对于成本高、不可逆或存在安全风险的决策，这一点尤其重要。采用相同输入、模型逻辑和实验设置，也有利于重现同一类仿真实验。

仿真的另一项价值是揭示直观推理不容易预见的动态结果。假设一家银行的平均服务能力看起来大于平均顾客到达量，仍不代表任何时刻都不会排队：短时间内的顾客集中到达，会造成队列积累，队列又需要一段时间才能消化。因此，仅比较两个平均数可能遗漏运行过程中的拥堵。

课件强调的 `what-if` 分析，是先提出“如果改变某一条件会怎样”，再用模型运行进行比较。比如增加一个服务窗口后，平均等待时间可能下降多少，资源闲置时间又会增加多少。仿真适用于具有不确定性和复杂相互作用的系统；当其他求解办法难以使用时，常被称为分析复杂问题的“最后的方法”。

### 1.3.2 缺点：能生成结果，但结果未必可靠

课件强调四个限制。

第一，带有随机输入的仿真输出具有抽样性质。某次运行出现五分钟平均等待，不代表实际系统在同一条件下长期平均等待一定是五分钟。要判断方案是否真的更好，需要合理安排多次运行，并采用统计方法分析输出的波动。

第二，直观的动画与报表可能使错误结论显得可信。如果模型漏掉关键约束、输入数据不符合实际，画面再真实、数字再精确，也不能代替对模型的验证与确认。

第三，仿真本身不自动完成优化。它可以回答“给定这个配置，结果怎样”，但不会仅凭运行一次就证明“这是所有配置中的最优方案”。如果需要求最优配置，就必须进一步设置候选方案比较、搜索或优化程序。

第四，仿真属于对现实系统的近似和描述性建模，不应因为能运行模型就忽视解析模型、理论分析或其他决策方法。面对一个可以直接算清楚的简单问题，不一定需要建立大型仿真模型。

## 1.4 什么时候适宜使用仿真？（课件第 15 页）

课件给出的情形不是按行业划分，而是按开展实际实验的困难程度和问题复杂程度划分。

| 适用情形 | 课件列举的对象 | 使用仿真的原因 |
| --- | --- | --- |
| 已有系统的实验与评估 | 生产加工过程、交通信号灯、超市存货策略 | 先在模型中比较不同运行规则，再考虑调整现实系统 |
| 昂贵或不可恢复的系统 | 车间布局、重要经济政策、航天器发射与控制、业务流程再造（BPR） | 直接试错成本高，或做出的改变难以撤回 |
| 未来系统的设计与分析 | 大型项目投资、可行性研究 | 真实系统尚未建成，无法直接收集其完整运行结果 |
| 危险的试验 | 涉及安全风险的系统运行情景 | 不适合为了取得数据而在现实中制造危险 |
| 难以使用解析方法的复杂问题 | 包含多种相互作用机制的系统 | 难以直接求出封闭形式的性能指标，可以通过实验估计 |

判断是否需要仿真时，要先问研究问题是否依赖运行过程及复杂相互作用。如果只需按照确定的费用和数量计算总成本，直接计算即可；如果总成本又受到随机到达、排队、资源竞争与运行规则共同影响，仿真实验就可能更有用。

## 1.5 仿真模型的分类（课件第 16—23 页）

课件从系统状态、时间特征和行为特征三个维度分类。三组分类标准是相互独立的，不能把“离散”“动态”“随机”当作互相排斥的三种类型。例如，一个银行排队模型就可能同时是离散的、动态的和随机的。

### 1.5.1 按状态特征：离散、连续和混合

| 类型 | 状态变化形式 | 课件实例及说明 |
| --- | --- | --- |
| 离散系统仿真 | 状态通常在特定事件发生时跳变，事件之间保持不变 | 排队系统、加工系统、通信系统 |
| 连续系统仿真 | 状态随时间连续演化，常通过微分方程或差分方程描述其变化 | 自动控制系统、导弹跟踪系统 |
| 混合系统仿真 | 同时包含离散事件变化与连续状态变化 | 需要联合表达两类机制的系统 |

课件第 19 页用两类状态轨迹作对比。离散系统中，队长可能在顾客到达时增加，在顾客离开队列进入服务时减少，而在两次事件之间保持常数。图形上表现为台阶状变化。连续系统中，飞行轨迹等状态可随时间持续变化，通常需要利用状态变化率及相应方程进行描述。

特别要区分“离散事件”与“离散时刻”。离散事件仿真不要求时间只能取整数；事件完全可以发生在 2.3 分钟或 5.8 分钟。它的特征是系统状态在事件时刻发生变化，而不是时间刻度必须离散化。

### 1.5.2 公共汽车引例：事件、状态和活动分别是什么？

课件第 20—21 页以某路公共汽车为例，始发站为北宫门，终点站为西直门，经过颐和园、圆明园、清华大学、五道口、北航等站点。此例把离散事件模型最重要的三个概念具体化。

| 概念 | 公共汽车模型中的含义 | 对模型运行的作用 |
| --- | --- | --- |
| 初始事件 | 公共汽车从北宫门出发 | 启动模拟的行程 |
| 状态变量 | 车上的乘客数量 | 描述某一时刻系统的状态 |
| 活动 | 相邻两站之间的行驶过程及行驶时间 | 使模拟时间从一站推进到下一站 |
| 事件 | 到站、离站 | 触发乘客数量或行程阶段的状态更新 |

在课件的简化设定中，公共汽车行驶于两站之间时，车上乘客数不变；发生到站、上下车和离站等事件后，乘客数量才可能改变。因此，如果把横轴画为时间、纵轴画为乘客数量，就会看到一段一段的水平线与事件时刻的跳变。站点之间的行驶时间可以是随机变量，乘客上下车数量也可能具有随机性。

需要注意两个层次：乘客数是“状态”，不是事件；“到站”是触发状态变化的事件，而“两站间行驶”是占据一段时间的活动。模型可根据研究目的进一步细分事件，但不能把这些概念混为一谈。

### 1.5.3 按时间特征：静态与动态

静态仿真不重点描述系统状态随时间推进的过程，主要关注一组条件下的随机实验或计算结果。动态仿真则把时间和状态演化纳入模型，研究事件发生或状态连续变化对后续运行的影响。

前面公共汽车沿途载客、银行顾客排队、工程活动依次开始和结束的例子，都需要描述过程随时间变化，因此属于动态分析思路。一个模型是不是动态的，要看研究问题是否需要保存状态演化和先后顺序，而不取决于结果报表有没有时间字段。

### 1.5.4 按行为特征：确定性与随机性

确定性仿真在给定初始状态、输入和运行规则后，模型行为由这些条件确定。随机仿真则含有随机输入或随机机制，即使配置方案不变，不同运行也可能出现不同结果。

例如，若公共汽车每一站的行驶时间和上下车人数全部固定，那么相同设置下的运行轨迹可以重复得到；如果行驶时间或上下车数量按概率分布生成，就需要分析多次运行的结果，而不宜只以一次行程代表全部情况。

分类时可以用下面的对照理解：

| 维度 | 判断的问题 | 常见选项 |
| --- | --- | --- |
| 状态特征 | 系统的状态怎样改变？ | 离散、连续、混合 |
| 时间特征 | 是否研究状态随时间演化？ | 静态、动态 |
| 行为特征 | 相同条件下的运行是否包含随机差异？ | 确定性、随机性 |

## 1.6 实施仿真的手段（课件第 24 页）

课件列出四种实现方式：手工仿真、通用计算机语言、专用仿真语言和仿真器。它们解决的是“用什么载体执行模型”，与上一节“所研究系统属于什么模型”是不同问题。

| 实施方式 | 基本做法 | 适合用来理解的重点 |
| --- | --- | --- |
| 手工仿真 | 用事件表、时间记录表和人工计算推进模型 | 便于看清事件先后、状态更新与统计量积累 |
| 通用计算机语言 | 自行编写数据结构、事件规则与统计计算程序 | 灵活，但需要处理实现和调试工作 |
| 专用仿真语言 | 使用面向仿真问题设计的语言描述系统运行 | 对事件、队列、资源等常见结构提供更直接的表达方式 |
| 仿真器或仿真软件包 | 借助专门软件提供的模块与界面建立并运行模型 | 减少重复编码，便于构建、运行与观察模型 |

例如，双服务台排队问题可以先用手工表格处理少量顾客，再用程序实现事件调度，也可以利用图形化仿真软件表示顾客流动和服务资源。无论采用哪种手段，都必须明确相同的到达规则、服务规则与状态更新规则。软件选型不会改变基本的系统逻辑。

## 1.7 实施仿真的步骤（课件第 25—26 页）

课件将仿真研究组织为从明确问题到输出分析和决策实施的一系列工作，并用流程图强调建模、检查和实验之间可以往返修改。

| 主要环节 | 这一环节需要完成的工作 | 可能产生的成果 |
| --- | --- | --- |
| 1. 明确问题、设定目标 | 说明研究对象、决策问题、衡量指标和系统范围 | 明确的研究目标与评价标准 |
| 2. 概念建模与逻辑建模 | 确定实体、活动、事件、状态及其关系，形成可执行逻辑 | 概念模型、逻辑模型 |
| 3. 数据采集与分析 | 收集系统输入、检查数据特性并确定模型采用的参数或分布 | 输入数据及其统计描述 |
| 4. 模型验证与确认 | 检查程序是否正确执行既定规则、模型是否足以代表实际系统 | 可接受的模型及其检查记录 |
| 5. 实验设计 | 设定候选方案、运行条件、实验次数及比较方式 | 可执行的仿真实验计划 |
| 6. 仿真运行 | 按设计运行模型，保存必要的状态与统计数据 | 各次运行的原始或汇总输出 |
| 7. 输出统计分析 | 估计系统性能、比较方案，判断结果的可靠程度 | 统计分析与决策报告 |
| 8. 决策与实施 | 依据问题目标解释结果并用于实际决策 | 方案选择及后续实施安排 |

第 25 页以七项列出主要步骤；第 26 页的详细流程图把建模拆成概念模型与逻辑模型，并在输出报告后接入“决策与实施”。所以在理解时，可以把它视为七个主要环节再加上成果应用，而不是两个互相矛盾的流程。

### 1.7.1 验证与确认为什么要分开？

验证（Verification）检查的是：模型是否已经被正确地实现。例如规定顾客按先到先服务排队，程序就应该按该规则取队首顾客；若程序在资源忙碌时仍让新顾客直接开始服务，属于实现逻辑问题。

确认（Validation）检查的是：模型所采用的系统规则、结构与数据是否能够恰当地代表实际系统。例如程序完全正确地实现了先到先服务，但真实银行存在不同类型顾客的优先办理规则，那么模型仍可能不够真实。

两者之所以都出现在流程图中，是因为“程序算对了”与“算的是正确的现实问题”是两项独立要求。验证失败可能需要修改程序，确认失败可能需要修改概念模型、逻辑模型或输入假设，因此都可能返回前面重新建模。

### 1.7.2 为什么运行后还要问“需要更多运行吗”？

课件第 26 页在仿真运行之后设置了是否需要追加运行的判断。当模型包含随机因素时，一次结果通常不足以稳定估计系统性能。研究者需要根据输出波动和精度要求决定是否补充实验，再进行统计分析。

因此，“运行完成”不等于“研究完成”。正确的顺序是先获得具有解释价值的输出，再检查结果是否充分，最后据此形成报告和决策。若发现结果不能回答起初设定的问题，也可能需要回到实验设计甚至问题定义阶段。

## 1.8 仿真的应用与发展（课件第 27—32 页）

本节按照课件给出的发展阶段整理。它介绍的是仿真方法与计算技术、建模工具及应用范围之间的变化关系，不是要求记忆每个年代的精确分界点。

| 阶段 | 课件列出的代表内容 | 主要变化 |
| --- | --- | --- |
| 奠基性工作 | 1773 年 Buffon 投针实验；20 世纪 20—30 年代 Shewhart 的随机抽样实验方法、Gosset 与相关抽样分布工作 | 随机实验与统计分析逐步形成方法基础 |
| 早期：20 世纪 40—60 年代 | Monte Carlo 方法的发展；20 世纪 60 年代 GPSS 出现 | 仿真开始借助计算机和专用工具，但运行成本高、使用门槛高 |
| 成熟期：20 世纪 70—80 年代 | 计算机效率提高、成本下降，仿真语言完善 | 大型企业用于重要问题分析，工业工程与运筹学教育开始系统讲授 |
| 20 世纪 80—90 年代 | 个人计算机普及，图形与动画进入仿真软件 | 仿真逐渐进入企业日常经营问题和投资论证 |
| 20 世纪 90 年代以后 | 高性能计算、友好人机界面、集成软件包及更方便的建模环境 | 仿真应用范围扩大，并更早进入经营与设计决策过程 |

课件第 28 页提及早期程序运行费用约为每小时 600—1000 美元。这是对当时成本条件的历史描述，不能用于估计现在使用仿真软件的费用。

### 1.8.1 课件列出的发展趋势

课件第 32 页把发展趋势概括为八个方向，它们侧重于仿真与其他技术、真实系统的联系逐渐增强。

| 发展方向 | 主要含义 |
| --- | --- |
| 与其他软件和应用系统集成 | 让仿真模型与业务数据、管理或工程软件协同工作 |
| 更方便的建模环境 | 降低建模和操作门槛，使建立模型更直接 |
| 行为建模与仿真 | 表达人的行为或虚拟人的行动机制 |
| 分布式并行仿真 | 通过网络协作、多主体或并行计算开展更复杂的模拟 |
| 基于互联网的仿真 | 利用网络、网格或云环境支持仿真任务 |
| 仿真与实际系统协同 | 对应课件提及的数字孪生方向，强调模型与实际系统之间的联系 |
| 可视化交互仿真的决策支持 | 结合 VR、AR 等交互手段展示、操作和理解仿真结果 |
| 虚拟与现实世界融合 | 课件以“元宇宙”概括更广泛的虚实融合方向 |

这些趋势涉及不同层面：有的改变建模界面，有的改变计算与协作方式，有的改变模型和现实数据之间的关系。它们不应被理解为八种互相排斥的仿真模型分类。

## 1.9 主要应用领域（课件第 33 页）

课件列出制造业、交通运输、项目管理、军事、航空航天、经济与金融、生命系统，以及医疗、餐饮等社会服务领域。不同领域采用仿真的共同出发点，是希望在给定系统结构和运行规则下观察结果、比较情景或分析不确定性。

制造业可以研究加工流程与资源占用；交通运输可以研究车辆运行与服务能力；项目管理可以研究任务之间的制约关系和完工风险；经济金融与社会服务可以研究业务流程及服务资源配置。军事、航空航天及生命系统等领域也可以利用仿真研究不便直接试验的系统行为。

课件在这一页列出的是应用领域，而不是为每一个领域都提供了可直接计算的专门模型。因此，学习本节应掌握应用范围及使用目的，不需要臆造课件未给出的案例参数或结果。

## 1.10 应用案例（课件第 34 页）

第 34 页仅给出“应用案例”的章节标题，没有可供复算的新案例数据。对本讲而言，可用前面已经出现的三个引例对应理解仿真建模的不同侧面。

| 课件中的引例 | 研究的系统 | 需要表达的核心机制 | 可以回答的问题 |
| --- | --- | --- | --- |
| 工程项目 | 多活动施工网络 | 活动先后关系与可能变化的工期 | 截止时间前完工的风险 |
| 银行运行 | 顾客和服务窗口组成的服务系统 | 顾客到达、排队、窗口配置和服务 | 不同配置下的等待与资源利用情况 |
| 公共汽车运行 | 按站点推进的运输服务系统 | 到离站事件、行驶活动和乘客数量状态 | 载客状态怎样随行程变化 |

课件第 35 页是参考教材页，不增加新的理论知识点。

## 本讲应当能够区分的概念

| 容易混淆的说法 | 应当如何区分 |
| --- | --- |
| “预计工期是 44 周”与“47 周按期完工概率是 84%” | 前者是一个工期计算结果，后者是考虑随机性后的概率陈述，不能互相代替 |
| 实际系统与仿真模型 | 实际系统是研究对象；模型是围绕研究目的建立的简化表达 |
| 离散系统与静态系统 | 前者按状态变化方式划分，后者按时间特征划分，分类维度不同 |
| 事件与活动 | 事件发生于特定时刻并可能改变状态；活动通常占据一定时间 |
| 状态变量与仿真输出指标 | 状态描述某一时刻的系统；输出指标通常从运行轨迹中统计或汇总而来 |
| 验证与确认 | 验证看模型是否正确实现，确认看模型是否适当代表现实 |
| 仿真分析与仿真优化 | 分析评价给定方案，优化还需要定义目标和寻找更优方案的程序 |

掌握本讲后，应能根据一个实际管理问题说明是否适宜使用仿真，指出系统的状态、事件和活动，按三个维度判断模型类型，并说明一份仿真报告为什么必须交代输入数据、模型检查和输出统计分析。
